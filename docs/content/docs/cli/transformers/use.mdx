The `use` system variable allows you to embed the contents of another text snippet directly into your current template. This is incredibly powerful for building reusable templates, signatures, and standardized components.

## Usage

Use the `use` system variable by passing the **trigger name** of the target snippet as a string argument. 

```markdown
[use("trigger_name")]
```

### Example

Suppose you have a snippet with the trigger `signature`:

```markdown
Thanks,
John Doe
Senior Developer | Example Corp
```

You can embed this signature into an `email_reply` snippet:

```markdown
Hi [0],

Thanks for reaching out! We are looking into this and will get back to you shortly.

[use("signature")]
```

When you type your `email_reply` trigger, Taurine automatically resolves and inserts the `signature` snippet in its place.

## Safety Limits & Validation

Because you can nest snippets (e.g., Snippet A uses Snippet B, which uses Snippet C), it's easy to accidentally create infinite loops or rack up large API bills using AI transformers. 

To protect your system, Taurine enforces two strict safety limits when you **save or update** a snippet:

1. **Max Recursion Depth of 5**: If your snippet chain exceeds 5 nested levels, Taurine will reject the save to prevent stack overflows.
2. **Max AI Calls of 3**: If your snippet (combined with all nested snippets) contains more than 3 `| ai` transformers in total, Taurine will reject the save to prevent runaway API quotas.

For more details on Taurine's architectural boundaries, read the [Rules & Limits](../reference/rules) reference guide.

## Error Handling

Taurine handles missing or invalid nested snippets gracefully during runtime interpolation:

- If you reference a snippet that does not exist in your database, the placeholder evaluates to: `[Error: Snippet 'name' does not exist]`.
- If you reference a script trigger instead of a text snippet, it evaluates to: `[Error: Cannot invoke non-text snippet 'name']`. 
*(Note: Nested script execution is disabled to prevent severe thread-locking and race conditions).*
