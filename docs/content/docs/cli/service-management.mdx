## Lifecycle Commands

You can control the background service using these core commands:

<Steps>
### Start the Service
```bash
nite up
```
This boots the engine and starts listening for your triggers.

### Check the Status
```bash
nite status
```
Verify if the service is running and check if the engine is currently paused.

### Restart the Service
```bash
nite restart
```
Useful for picking up configuration changes or resetting the engine state.

<Callout title="Hot Reload" type="info">
  You won't need to restart manually very often! Nite automatically reloads its memory whenever you add, update, or delete a trigger.
</Callout>

### Stop the Service
```bash
nite down
```
Gracefully shuts down the background service.
</Steps>

### Aliases

If you prefer more traditional naming, these aliases are also available:

| Alias | Core Command |
| :--- | :--- |
| `nite start` | `nite up` |
| `nite stop` | `nite down` |
| `nite reboot` | `nite restart` |

## Windows

- `nite up` starts the background service if it is not already running.
- If `start_on_boot` is enabled, Nite creates a startup hook in the Windows Run registry key and uses a small VBS launcher to start `nite --daemon` silently.
- `nite down` tries a graceful shutdown first, then falls back to killing the process if needed.

## Linux And macOS

- Nite uses a user-level service manager.
- `nite up` installs the service if needed, then starts it.
- `start_on_boot` controls whether the service is installed with autostart enabled.

<Callout title="Linux permission note" type="warn">
  On Linux, Nite may ask for extra permissions so it can listen for input events. If it adds
  your user to the `input` group, you must log out and back in before the change takes effect.
</Callout>

## Status Output

`nite status` tells you whether Nite is running. If the engine is paused, it also shows the current pause hotkey.
