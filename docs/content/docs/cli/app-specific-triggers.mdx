App-Specific Triggers allow you to define automations that only execute when certain applications, window classes, or window titles are actively focused. This prevents global triggers from accidentally firing in applications where they aren't meant to be used (like games, terminals, or password managers) and allows you to bind the same hotkey to different actions depending on the active application.

## How it works

When an automation specifies app filters, Taurine inspects the active window's details at the exact moment the trigger is matched. You can configure filters using two command-line flags:

* `--include-apps <list>`: A comma-separated list of application rules. The automation will **only** fire if the active window matches at least one of these rules.
* `--exclude-apps <list>`: A comma-separated list of application rules. The automation will **never** fire if the active window matches any of these rules.

## Prefix Specifiers

Each rule in the list can use a prefix specifier to target a specific window property:

* **`exe:<name>`**: Matches the process executable/binary name (case-insensitive exact match).
  * *Example:* `exe:code` matches `code` (or `code.exe` on Windows).
  * *Full Paths:* If the value contains path separators (`/` or `\`), it matches against the **exact full path** of the binary. E.g., `exe:C:\Windows\notepad.exe`.
* **`class:<name>`**: Matches the window class name or macOS bundle ID (case-insensitive exact match).
  * *Example:* `class:CabinetWClass` (Windows Explorer) or `class:com.google.Chrome` (macOS).
* **`title:<substring>`**: Matches a substring in the active window title (case-insensitive substring match).
  * *Example:* `title:GitHub` matches any focused window containing "GitHub" in its title (e.g. browser tabs or editor titles).
* **Default (no prefix):** If you don't supply a prefix (e.g., `chrome`), it defaults to `exe:` matching. E.g., `chrome` is equivalent to `exe:chrome`.

## Where to Find Application Labels in Your OS

To configure your filters accurately, look up the target application label in the following OS-specific locations:

* **Windows:** Look at the process executable name in **Task Manager** under the **Details** tab (case-insensitive, you can omit the `.exe` extension).
  * *Examples:* `code` (VS Code), `chrome` (Google Chrome), `notepad` (Notepad).
* **macOS:** Look at the **localized application name** displayed in the top-left menu bar next to the Apple logo.
  * *Examples:* `Visual Studio Code`, `Google Chrome`, `Terminal`.
* **Linux (X11):** Look at the **window class name** (`WM_CLASS`), which can be queried by running `xprop WM_CLASS` in your terminal and clicking on the target window.
  * *Examples:* `code`, `google-chrome`, `gnome-terminal`.

## Examples

### Restricting to specific apps
Create a hotkey that only works when editing code in VS Code or browsing in Google Chrome:

```bash
taurine add --hotkey "ctrl+shift+e" --include-apps "exe:code,exe:chrome" "Insert current date"
```

### Restricting based on website / window title
Create a snippet that only expands when you are actively viewing GitHub in your browser:

```bash
taurine add pr "git pull" --include-apps "title:GitHub"
```

### Blocking in specific apps
Create a trigger that works everywhere *except* inside Slack and terminal windows:

```bash
taurine add "!deploy" "curl -X POST https://api.example.com/deploy" --exclude-apps "exe:slack,exe:cmd,exe:windowsterminal"
```

### Reusing the same hotkey
Because filters prevent overlap, you can bind the same hotkey to different actions across different applications:

```bash
# In VS Code, trigger quick open file
taurine add --hotkey "ctrl+p" --include-apps "exe:code" "workbench.action.quickOpen"

# In Google Chrome, print the page
taurine add --hotkey "ctrl+p" --include-apps "exe:chrome" "window.print()"
```

<Callout title="Trigger Conflicts" type="warning">
  If you attempt to map the same hotkey/trigger on overlapping applications (for example, mapping one to run only in Chrome and another to run globally), Taurine will reject it with a `Trigger conflict` error to protect your key bindings from colliding.
</Callout>

## Safety & Fail-Safes

* **Strict Mode on Query Failure:** If the operating system fails to determine the active window (due to secure screens, lock screens, OS transitions, or permission limits), Taurine **safely blocks** any restricted automation from firing. This ensures that sensitive expansions never leak into untrusted windows.
* **Wayland Support (Linux):** Because Wayland restricts global active window queries, active application filtering is bypassed on Wayland (restricted automations are safely blocked), defaulting to standard global behavior for unrestricted triggers.
