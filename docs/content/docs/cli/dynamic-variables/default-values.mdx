## Mandatory Default Values

To ensure that variables always have a predictable fallback, Taurine requires that every unique dynamic variable defines a default value using the `=` symbol on its first appearance: `[$name = "there"]`.

Subsequent occurrences of the same variable in the template automatically inherit the default and do not require repeating it:

```text
[$first = "John"] [$last = "Doe"] (Welcome, [$first]!)
```

### Quoting Rules

- **Unquoted:** Simple single-word alphanumeric defaults do not require quotes: `[$name = there]`.
- **Quoted:** If your default contains spaces, punctuation, or special characters, wrap it in double quotes (`"`) or single quotes (`'`): `[$message = "No content provided"]`.
- **Empty Defaults:** Explicit empty string defaults are permitted when wrapped in quotes: `[$notes = ""]`.

<Transformation
  template='Message: [$content = "No content provided"]'
  cases={[
    { input: "msg", result: "Message: No content provided" },
    { input: 'msg;"Hello World"', result: "Message: Hello World" },
  ]}
/>

If no value is provided via input, Taurine will use the assigned default.

<Callout type="warning" title="Strict Declaration Rule">
  Taurine will reject your template at save time if a dynamic variable lacks a default value on its declaration (e.g., `[$name]` with no prior definition) or if an unquoted empty default is provided (e.g., `[$name=]`).
</Callout>
