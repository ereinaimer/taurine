## Mandatory Default Values

To ensure that variables always have a predictable fallback, Taurine strictly requires that every unique dynamic variable defines a default value using the `=` symbol.

### Optional vs Required Quotes (Hybrid Syntax)

Taurine uses a smart parser that makes your life easier:
- **Optional:** You don't need quotes for simple alphanumeric defaults. E.g., `[name=there]`
- **Required:** You **must** wrap your default value in quotes (`"` or `'`) if it contains spaces, commas, or closing brackets. E.g., `[message="No content provided"]`

<Transformation
  template="Message: [content=\"No content provided\"]"
  cases={[
    { input: ">msg", result: "Message: No content provided" },
    { input: ">msg:\"Hello World\"", result: "Message: Hello World" },
  ]}
/>

If no value is provided via input, Taurine will use the assigned default. 

<Callout type="warning" title="Strict Parsing Rule">
  Taurine will **reject** your template and prevent saving if a dynamic variable lacks a default value (e.g., `[name]`) or if the default value is empty (e.g., `[name=]`). 
  
  If you intend to write literal text that includes brackets without it being treated as a variable, you must escape it with a backslash like `\\[name\\]`.
</Callout>

## Real-World Examples
Default values turn templates into smart tools that work out of the box while remaining fully customizable. 

<Accordions>
  <Accordion title="Show Productivity Examples">
    <div className="text-lg font-bold mt-4 mb-1">Friendly Greetings</div>
    Keep your communications professional even when you're in a rush by using a fallback for names.
    
    **Trigger:** `>hi`
    
    ```text trigger=">hi "
    Hi [name=there], thanks for reaching out!
    ```

    <Callout type="info">
      **Try it:** Type `>hi` for the default greeting, or `>hi:Erein` to personalize it.
    </Callout>
  </Accordion>
  <Accordion title="Show Developer Examples">
    <div className="text-lg font-bold mt-4 mb-1">Standardized Git Commits</div>
    Maintain a consistent commit style by defaulting to your most common commit type.
    
    **Trigger:** `>gc:::'Initial commit'`
    
    <Callout type="info">
      **Pro Tip:** Use double colons `::` to skip a placeholder and use its default value. In this example, we skip `type` and `scope` to use their defaults.
    </Callout>
    
    ```text trigger=">gc:::'Initial commit' "
    [type=feat]([scope=cli]): [message="default message"]
    ```
  </Accordion>
</Accordions>

<Callout type="info" title="Experiment!">
  Click the **Play** button on any of the code blocks above to test these out. Defaults are especially powerful when combined with multiple variables—try skipping arguments with `::` to see the logic in action!
</Callout>
