## Positional Arguments

Use numbered placeholders `[0]`, `[1]`, etc., to reference arguments strictly by the order you type them. This allows you to reorder inputs in your final output.

**Example Template:**
```text
https://github.com/[1]/[0]
```

**Input:** `>gh:taurine:ereinaimer`  
**Result:** `https://github.com/ereinaimer/taurine`

By using `[1]` before `[0]`, Taurine swapped the order of the organization and the repository name. You have complete control over where each input goes, regardless of the order you typed them.

## Named Arguments

Explicitly assign a value to a label using the `key=value` format when typing your trigger. This is useful when you want to ignore the order of arguments entirely.

**Example Template:**
```text
Repo: [repo] by [name]
```

**Input:** `>gh:name=ereinaimer:repo=taurine`  
**Result:** `Repo: taurine by ereinaimer`

Named arguments override their position. Even though `name` was typed first, it correctly filled the `[name]` placeholder at the end of the template.

## Quoted Arguments

Quotes allow arguments to contain spaces or colons without breaking the trigger parsing. Taurine supports both double quotes (`"`) and single quotes (`'`), which allows you to nest quotes or include apostrophes easily.

**Example Template:**
```text
Quote: [0]
```

**Input:** `>quote:'"One small step for man"'`  
**Result:** `Quote: "One small step for man"`

**Input:** `>quote:"How're you?"`  
**Result:** `Quote: How're you?`

By wrapping the text in quotes, you can preserve complex strings, including those that contain other quote characters or punctuation, as a single argument.

## Sequential Positional Fallback

If a placeholder is not numbered and does not match a named argument, Taurine will fill it from the next available positional value.

**Example Template:**
```text
Player 1: [p1], Player 2: [p2]
```

**Input:** `>match:Mario:Luigi`  
**Result:** `Player 1: Mario, Player 2: Luigi`

Taurine automatically maps `Mario` to the first unassigned placeholder (`p1`) and `Luigi` to the second (`p2`). This keeps your templates readable without needing to manage index numbers manually.
