## Positional Arguments

Use numbered placeholders `[0]`, `[1]`, etc., to reference arguments strictly by the order you type them. This allows you to reorder inputs in your final output.

<Transformation
  template="https://github.com/[1=repo]/[0=org]"
  input=">gh:taurine:ereinaimer"
  result="https://github.com/ereinaimer/taurine"
/>

By using `[1=repo]` before `[0=org]`, Taurine swapped the order of the organization and the repository name. You have complete control over where each input goes, regardless of the order you typed them.

## Named Arguments

Explicitly assign a value to a label using the `key=value` format when typing your trigger. This is useful when you want to ignore the order of arguments entirely.

<Transformation
  template="Repo: [repo=default_repo] by [name=default_name]"
  input=">gh:name=ereinaimer:repo=taurine"
  result="Repo: taurine by ereinaimer"
/>

Named arguments override their position. Even though `name` was typed first, it correctly filled the `[name=default_name]` placeholder at the end of the template.

## Quoted Arguments

Quotes allow arguments to contain spaces or colons without breaking the trigger parsing. Taurine supports both double quotes (`"`) and single quotes (`'`), which allows you to nest quotes or include apostrophes easily.

<Transformation
  template="Quote: [0=empty]"
  cases={[
    { input: ">quote:'\"One small step for man\"'", result: 'Quote: "One small step for man"' },
    { input: ">quote:\"How're you?\"", result: "Quote: How're you?" },
  ]}
/>

By wrapping the text in quotes, you can preserve complex strings, including those that contain other quote characters or punctuation, as a single argument.

<Callout type="info" title="Action Key & Unquoted Spaces">
  If your `action_key` is set to `enter` (the default), arguments can contain spaces without needing quotes (e.g. `>hi:erein aimer: how was your day`). However, if your `action_key` is set to `space`, or if you need to include colons (`:`) within your arguments, you must wrap them in quotes.
</Callout>

## Strict Mapping & Non-Greedy Fallbacks

If a placeholder is not numbered and does not match a named argument, Taurine will **not** consume positional values sequentially. Instead, it strictly respects the variable mapping, leaving the placeholder to use its default value.

<Transformation
  template='Repo: [repo="taurine"] / User: [0="erein"]'
  input=">gh:aimer"
  result="Repo: taurine / User: aimer"
/>

Taurine maps `aimer` to `[0="erein"]`, leaving `[repo="taurine"]` to safely fall back to its default value.

## Real-World Examples
Mastering arguments allows you to build templates that are both structured and highly reusable.


    Navigate to repos within a specific organization by using positional mapping.
    
    **Trigger:** `>gh:ereinaimer:taurine`
    
    ```text trigger=">gh:ereinaimer:taurine "
    https://github.com/[0=org]/[1=repo]
    ```
  </Accordion>
</Accordions>

<Callout type="info" title="Take Note!">
  Position indexing starts at **0**. If you have three arguments, they will be mapped to `[0=a]`, `[1=b]`, and `[2=c]` in the order they appear in your trigger.
</Callout>
