title: Arguments
description: Fill named fields inline with bare or labeled values.
---

## Bare Values Fill in Order

Write one template with named fields, then fill values inline separated by semicolons (`;`). Bare values fill named fields in template definition order, followed by Enter.

<Transformation
  template="Meet at [time=now] in [place=here]"
  input="meet;2pm;the lobby"
  result="Meet at 2pm in the lobby"
/>

## Named Arguments

Explicitly assign a value to a label using the `key=value` format when typing your trigger. Explicit names always win regardless of position, and matching is case-insensitive.

<Transformation
  template="Repo: [repo=default_repo] by [name=default_name]"
  input="gh;name=ereinaimer;repo=taurine"
  result="Repo: taurine by ereinaimer"
/>

Named arguments override position. Even though `name` was typed first, it correctly filled the `[name=default_name]` placeholder at the end of the template. Order in the template does not matter either: with `Repo: [repo=x] by [name=y]`, `gh;name=erein;repo=taurine` still fills each field by name.

## Quoted Arguments

Quotes allow arguments to contain spaces or semicolons without breaking the trigger parsing. Taurine supports both double quotes (`"`) and single quotes (`'`), which allows you to nest quotes or include apostrophes easily.

<Transformation
  template="Quote: [message=empty]"
  cases={[
    { input: "quote;'\"One small step for man\"'", result: 'Quote: "One small step for man"' },
    { input: "quote;\"How're you?\"", result: "Quote: How're you?" },
  ]}
/>

By wrapping the text in quotes, you can preserve complex strings, including those that contain other quote characters or punctuation, as a single argument.

Arguments can contain unquoted spaces without needing quotes (e.g. `hi;erein aimer; how was your day`). Colons (`:`) are ordinary text and need no quoting (e.g. `meet;12:30;the lobby`).

## Ordered Fallback & Skipping

Bare values fill named fields in the order the fields appear in the template, skipping fields already satisfied by an explicit `key=value`. Missing values use their defaults. An empty segment (`;;`) never fills empty text — it always keeps the default, so you can skip a field.

<Transformation
  template='Repo: [repo="taurine"] / User: [user="erein"]'
  input="gh;;aimer"
  result="Repo: taurine / User: aimer"
/>

Taurine skips `[repo="taurine"]` via the empty segment and fills `[user="erein"]` with `aimer`, leaving anything unfilled on its default value.

## Real-World Examples
Mastering arguments allows you to build templates that are both structured and highly reusable.

<Callout type="info" title="Previously colons">
  Older guides separated arguments with `:` (e.g. `gh:taurine`). That syntax is retired: `:` is now ordinary text, so `meet:2pm` no longer passes arguments — type `meet;2pm` instead.
</Callout>
