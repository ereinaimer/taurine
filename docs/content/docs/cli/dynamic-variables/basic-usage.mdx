Dynamic variables are the secret sauce that makes your Taurine snippets truly flexible. Instead of static text, they allow you to create templates that react to the context of your input—turning simple macros into powerful trigger tools.

The core syntax uses square brackets with a mandatory `=` to define the variable and its fallback value: `[variable_name=default]`.

If you omit the `=`, Taurine will treat the bracket contents as literal text and leave it unchanged.

### Escaping Brackets
If you need a literal square bracket in your output that is **not** a variable at all, prefix it with a backslash: `\[` outputs `[`, and `\]` outputs `]`.

This is useful when writing code snippets or documentation where you want the brackets to remain visible in the expanded text instead of being replaced.

```text
Result: \[0\] + 1 = [value=1]
→ Result: [0] + 1 = 1
```

When Taurine encounters a bracketed word, it converts it into an **input mapping**. Anything you type after the colon (`:`) in your trigger is captured and injected directly into that placeholder at the moment of expansion.

No prefix character is needed — type the trigger word, append your argument after a colon (e.g., `hello:Erein`), and press **Enter** to expand.

### Basic Mapping
If your snippet has a single variable, Taurine maps the entirety of your terminal argument to that specific placeholder.

<Transformation
  template="Hello, [name=stranger]!"
  input="hello:Erein"
  result="Hello, Erein!"
/>

### Multi-Variable Snippets
You aren't limited to just one variable. You can scatter placeholders throughout your text to build sophisticated templates.

<Transformation
  template="GRANT ACCESS TO [user=guest] ON [environment=sandbox]"
  input="access:admin:staging"
  result="GRANT ACCESS TO admin ON staging"
/>

By adding more colons to your trigger, you can pipe multiple arguments into your snippet in one go.
