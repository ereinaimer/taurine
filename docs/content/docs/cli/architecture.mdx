Taurine is built with a high-performance, split-process architecture designed to ensure that text expansion and keyboard automation never lag your system, even during complex script executions.

## Single Binary, Two Roles

Despite being a single binary file, the application behaves differently depending on how it is invoked.

1.  **The Daemon (Background)**: The core engine that listens for keyboard events, manages the expansion pipeline, and executes automations. It runs silently in the background when the `--daemon` flag is passed.
2.  **The CLI (Frontend)**: The command-line interface you use to add, remove, and list automations.

## gRPC Communication

The CLI and the Daemon communicate using **gRPC** (Google Remote Procedure Call) over a local loopback connection. 

- When you run `taurine add ...`, the CLI serializes your request and sends it to the Daemon.
- The Daemon validates the request, updates its internal database, and reloads its state instantly without needing a restart.
- This ensures that your automations are available system-wide the moment you press Enter on a CLI command.

## The Engine Toggle

Sometimes you might want to temporarily disable Taurine (e.g., when playing a game or using a specific app where the trigger character `>` is used frequently). 

Taurine provides a configurable global system hotkey to toggle the expansion engine on and off:

| Action | Hotkey |
| :--- | :--- |
| **Toggle Engine** | `Alt` + `` ` `` (Backtick) |

When the engine is toggled off, the Daemon continues to run but stops intercepting keyboard events. Pressing the hotkey again restores full functionality immediately.

## Performance & Security

- **Security & Privacy First**: Taurine is designed to be invisible and secure. It does not require administrative privileges for standard text expansion and respects your system's security boundaries.
- **Memory Safety**: Written entirely in Rust, Taurine leverages memory safety and zero-cost abstractions for extremely low resource usage.
- **Process Isolation**: Shell scripts and background tasks are executed in isolated child processes with strict timeouts to prevent system-wide stalls.
- **Local First**: All data is stored in a local SQLite database and all communication stays on your machine. Taurine does not "call home" or send your keystrokes to any external servers.
- **No Vendor Lock-in**: You own your data. You can export your entire automation database at any time using the `taurine export` command, ensuring you can move your triggers to another system or backup if needed.
