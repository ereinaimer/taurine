Taurine provides a robust exchange system that allows you to back up your local environment or sync your triggers across different machines. Files are stored with the `.tau` extension and can be either encrypted or plaintext.

## Exporting Data

The `export` command bundles your triggers and optionally your global settings and stats into a single portable file.

```bash
# Opens an interactive TUI (default)
taurine export

# Export to a specific file with extras (opens TUI)
taurine export backup.tau -st

# Non-interactive — skips the TUI, uses provided flags directly
taurine export backup.tau -y --plain -stx
```

### Interactive vs Headless

By default, `export` opens an interactive TUI overlay where you can configure all options — encryption, file path, settings, stats, and sensitive data — before proceeding. All CLI flags are optional and pre-fill the form.

Pass `-y` / `--yes` to skip the TUI entirely and run non-interactively. With `--yes`:
- The file path defaults to `tx-YYMMDD.tau` if not provided.
- `--plain` is required for unencrypted export; otherwise the command errors because an encryption password can't be prompted for.

### Encryption & Security
By default, exports are encrypted using **AES-256-GCM**. You will be prompted to enter and confirm an encryption password. 

- **TAU1**: Encrypted binary format.
- **TAUP**: Plaintext JSON format (use `--plain` / `-p`).

<Callout title="Sensitive Data Filtering" type="warn">
  To protect your privacy, Taurine automatically filters out "sensitive" settings during export. Any setting key containing `password`, `secret`, `token`, or `api_key` is excluded from the exchange file by default. 
  
  To include sensitive settings, use the `-x` or `--sensitive` flag during export (e.g., `taurine export -tsx`). This flag requires encryption to be active.
</Callout>

## Importing Data

The `import` command allows you to load an exchange file into your local Taurine database.

```bash
# Opens an interactive TUI (default)
taurine import backup.tau

# Non-interactive — skips the TUI
taurine import backup.tau -y --conflict skip --settings
```

### Interactive vs Headless

Like `export`, `import` opens an interactive TUI overlay by default. All CLI flags (`--conflict`, `--settings`, `--stats`, `--sensitive`) are optional and pre-fill the form.

Pass `-y` / `--yes` to skip the TUI. A file path is always required with `--yes`. If the file is encrypted, the command errors because a decryption password can't be prompted for — use the interactive TUI or import a plaintext file.

### Conflict Resolution
When an imported trigger shares the same **Trigger** and **Target OS** as an existing local trigger, Taurine triggers a conflict resolution flow.

- **`prompt` (Default)**: Opens an interactive menu for each conflict.
- **`overwrite`**: Automatically replaces local triggers with the imported versions.
- **`skip`**: Ignores imported triggers that already exist locally.

<Callout title="Interactive Menu Options" type="info">
  When using `prompt`, you can choose to overwrite/skip for the current item, or use **Overwrite All** / **Skip All** to handle all remaining conflicts in one go.
</Callout>

### Handling Stats
If an exchange file contains stats, you can choose how to integrate them:

- **`merge` (Default)**: Combines local and imported stats. It sums the execution counts and preserves the most recent `last_used_at` timestamp.
- **`overwrite`**: Replaces your local stats history with the data from the exchange file.
- **`ignore`**: Discards stats from the import entirely.

## Technical Specifications

Taurine's exchange engine is designed for reliability and consistency:

| Feature | Specification |
| :--- | :--- |
| **Atomic Imports** | Imports are wrapped in a single database transaction. If one item fails, the **entire** import is rolled back to prevent data corruption. |
| **Script Handling** | Scripts are decompressed into human-readable text during export (if plaintext) and re-compressed using `zstd` upon import. |
| **Platform Metadata** | `target_os` metadata is preserved, ensuring your Windows-only scripts don't accidentally run on your Mac after an import. |


<Callout title="Atomic Reliability" type="success">
  You never have to worry about a "partial" import. If you lose power or the script crashes mid-way, your database remains exactly as it was before the command started.
</Callout>
