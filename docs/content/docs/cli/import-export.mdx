Taurine provides a robust exchange system that allows you to back up your local environment or sync your automations across different machines. Files are stored with the `.tau` extension and can be either encrypted or plaintext.

## Exporting Data

The `export` command bundles your automations and optionally your global settings and metrics into a single portable file.

```bash
# Basic encrypted export (creates taurine-export-YYYY-MM-DD.tau)
taurine export

# Export to a specific file with extras
taurine export backup.tau --with-settings --with-metrics
```

### Encryption & Security
By default, exports are encrypted using **AES-256-GCM**. You will be prompted to enter and confirm an encryption password. 

- **TAU1**: Encrypted binary format.
- **TAUP**: Plaintext JSON format (use `--no-encrypt`).

<Callout title="Sensitive Data Filtering" type="warn">
  To protect your privacy, Taurine automatically filters out "sensitive" settings during export. Any setting key containing `password`, `secret`, `token`, or `api_key` is excluded from the exchange file.
</Callout>

## Importing Data

The `import` command allows you to load an exchange file into your local Taurine database.

```bash
taurine import backup.tau --on-conflict prompt
```

### Conflict Resolution
When an imported automation shares the same **Trigger** and **Target OS** as an existing local automation, Taurine triggers a conflict resolution flow.

- **`prompt` (Default)**: Opens an interactive menu for each conflict.
- **`overwrite`**: Automatically replaces local automations with the imported versions.
- **`skip`**: Ignores imported automations that already exist locally.

<Callout title="Interactive Menu Options" type="info">
  When using `prompt`, you can choose to overwrite/skip for the current item, or use **Overwrite All** / **Skip All** to handle all remaining conflicts in one go.
</Callout>

### Handling Metrics
If an exchange file contains metrics, you can choose how to integrate them:

- **`merge` (Default)**: Combines local and imported stats. It sums the execution counts and preserves the most recent `last_used_at` timestamp.
- **`overwrite`**: Replaces your local metrics history with the data from the exchange file.
- **`ignore`**: Discards metrics from the import entirely.

## Technical Specifications

Taurine's exchange engine is designed for reliability and consistency:

| Feature | Specification |
| :--- | :--- |
| **Atomic Imports** | Imports are wrapped in a single database transaction. If one item fails, the **entire** import is rolled back to prevent data corruption. |
| **Script Handling** | Scripts are decompressed into human-readable text during export (if plaintext) and re-compressed using `zstd` upon import. |
| **Platform Metadata** | `target_os` metadata is preserved, ensuring your Windows-only scripts don't accidentally run on your Mac after an import. |
| **Reserved Triggers** | Imports strictly block any automation that attempts to claim the reserved `>ai` trigger. |

<Callout title="Atomic Reliability" type="success">
  You never have to worry about a "partial" import. If you lose power or the script crashes mid-way, your database remains exactly as it was before the command started.
</Callout>
