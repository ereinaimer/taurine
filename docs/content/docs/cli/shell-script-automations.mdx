Shell Script Automations are the most powerful feature in Taurine. They allow you to bridge the gap between simple text expansion and full system automation. By mapping a trigger to a script, you can open applications, manage files, fetch data from APIs, or trigger complex devops pipelines—all without leaving your text editor.

<Callout title="Infinite Possibilities" type="info">
  While standard snippets are for text, scripts are for **actions**. This feature opens the door to infinite possibilities for customizing your OS and workflow.
</Callout>

## Adding Scripts

You can add scripts directly from the command line or by pointing to an existing file on your disk.

### Inline Scripts
Use for quick, one-line commands.

```bash
taurine add script url 'start https://[url=google.com]' --lang powershell --os windows
```

### Script Files
Use for complex logic. Taurine will read the file, compress it, and store it in its internal database.

```bash
taurine add script deploy -f ./scripts/deploy.py
```

<Callout title="File Persistence" type="warn">
  When you add a script via `-f`, Taurine copies and compresses the content into its database. You do **not** need to keep the original file on your disk for the automation to work.
</Callout>

## Language Support & Inference

Taurine supports all major system interpreters. If you don't specify a language with `--lang`, Taurine will attempt to infer it.

| Language | Identifier | Inference Extensions |
| :--- | :--- | :--- |
| **Bash** | `bash` | `.sh` |
| **PowerShell** | `powershell` | `.ps1` |
| **Python** | `python` | `.py` |
| **Node.js (CommonJS)** | `node` | `.js`, `.cjs` |
| **Node.js (ESM)** | `node-esm` | `.mjs` |
| **Windows CMD** | `cmd` | `.bat`, `.cmd` |

### How Inference Works
1. **Extension**: Taurine first looks at the file extension if added via `-f`.
2. **Shebang**: If no extension is found (or it's an inline script), Taurine inspects the first line for a shebang (e.g., `#!/bin/bash`).
3. **Fallback**: If both fail, you must provide the `--lang` flag explicitly.

## Execution Modes

The `--mode` (or `-m`) flag determines how the script's output interacts with your text field.

- **`inline` (Default)**: The standard output (`stdout`) of the script is captured and injected into your text field as if it were a snippet.
- **`silent`**: The script runs in the background. No text is injected, even if the script prints to the console. This is ideal for background tasks like triggering a notification or starting a build.

```bash
# Inline: Injects "Hello, World" into your text
taurine add script hi "echo 'Hello, World'" -m inline

# Silent: Deletes a file quietly without typing anything
taurine add script cleanup "rm temp.log" -m silent
```

## Powering Scripts with Variables

The true power of scripting comes from combining it with [Dynamic Variables](/docs/cli/dynamic-variables) and [System Variables](/docs/cli/system-variables/index).

### Example: Smart URL Opener
This script uses a dynamic variable with a default value. If you type `>url Space`, it opens Google. If you type `>url:youtube.com Space`, it opens YouTube.

```bash
taurine add script url 'start https://[url=google.com]' --lang powershell --os windows
```

### Example: Environment-Aware Script
Access system metadata like your current user or home directory using `[env.*]`.

```bash
# Greets the currently logged-in user
taurine add script whoami "echo 'Hello, [env.USERNAME]!'" --lang bash
```

## Technical Details

- **Timeouts**: Every script expansion has a maximum execution time of **20 seconds**. If it takes longer, Taurine will terminate the process and return an error.
- **Environment**: Scripts are executed with the same environment as the Taurine daemon. Ensure your interpreters (`python`, `node`, etc.) are available in your system's `PATH`.
- **CWD**: Scripts are executed in a temporary directory. Always use absolute paths (via variables like `[env.USERPROFILE]`) when interacting with specific files on your system.
- **Cross-Platform**: Use the `--os` flag to define different versions of a trigger for `windows`, `linux`, or `macos`.
